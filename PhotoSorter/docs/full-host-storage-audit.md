# MAP: полный файловый аудит сервера (только чтение)

## Что делает сканер

`PhotoSorter/tools/maintenance/audit_host.py` запускается **на хосте** с правами root.
Он обходит именно файловые метаданные, не читает содержимое фотографий, пароли,
PostgreSQL, сертификаты или конфигурации Docker.

Отчёт включает отдельными областями:

1. Весь каталог проекта, включая Git, установщик, исходники, данные, образцы,
   оригиналы ФО, результаты, ZIP, кэш MegaLoc и веса моделей.
2. Docker root целиком: подключённые и простаивающие тома PostgreSQL/Caddy,
   контейнерные файлы и логи, собственные writable-слои контейнеров,
   слои Docker-образов, BuildKit, каталоги Docker со служебными метаданными.
   Каталоги `overlay2/*/merged` **не обходятся**: это повторные представления
   тех же файлов и других системных mountpoint.
3. Обнаружение контейнеров и томов по Compose project name `outdoor-sorter`.
4. Отдельное сопоставление Docker image layer cache-id при использовании overlay2.
   Слои общие, поэтому отмечены как *shared*, а не как эксклюзивная собственность MAP.
5. Связанные системные каталоги `/var/lib/containerd`, `/var/log`,
   `/var/cache/apt`, `/tmp`, `/var/tmp`, `/run`. Эти области *shared*
   и **не приписываются** MAP целиком.
6. Файлы из текущих `/tmp`, `/var/tmp` и `/dev/shm` каждого
   работающего контейнера через `/proc/<pid>/root`. Это альтернативный вид
   на файловую систему, поэтому его блоки не суммируются повторно.
7. Файлы, уже удалённые из каталогов, но **ещё открытые**
   процессами MAP-контейнеров (`/proc/<pid>/fd`) — если они открыты
   в момент проверки.
8. Карта потенциальных мест записи файлов в Python, shell-скриптах и Dockerfile:
   где код может создать временный объект, ZIP, файл или запустить внешний процесс.
   Она сохраняется в \`latest-write-sites.csv\`. Исходные пользовательские файлы
   не читаются даже этой проверкой.
9. Файлы хостовых Docker/Python пакетов и сетевых конфигураций,
   установленных установщиком (в отдельной общей категории).

Файлы, каталоги, символьные ссылки и специальные объекты перечисляются
без следования по symlink; физически занятые блоки учитываются по
`(device, inode)`, так что hardlink не увеличивает итог дважды.

## Как запустить

После обновления MAP при `sudo bash install.sh --deploy` полный аудит
автоматически выполняется в конце установки. Если установка сделана без root
или нужно повторить снимок, в терминале VPS:

```bash
cd /opt/Sorter
sudo python3 PhotoSorter/tools/maintenance/audit_host.py --project-root /opt/Sorter
```

После выполнения открой «Администрирование» → «Аудит всего сервера MAP».
Там доступны сводка, отдельные категории, предупреждения и кнопка скачивания
**полного CSV** и отдельная карта потенциальных мест записи.
Файлы находятся в
`PhotoSorter/data/audits/host/latest.csv` и `latest.json`.
При следующем запуске обновляются **только эти три собственных отчёта**.

## Что CSV означает, а чего не гарантирует

- `scope=app`: метаданные самого проекта, его контейнеров, томов и writable-слоёв.
- `scope=app_shared_layer`: слои Docker-образов, которые использует MAP.
- `scope=shared_unattributed`: системные каталоги, пакеты, Docker cache
  и файлы, которые могут использовать другие проекты.
- `scope=runtime_view`: дополнительные виды на временные каталоги,
  **не добавляются повторно** в физический итог.
- В `latest.json` перечислены все недоступные области и пропуски.

Это **снимок момента**, не неуязвимый журнал всех когда-либо созданных файлов.
Файлы, созданные и удалённые между проверками, невозможно восстановить
задним числом. Для их полной истории потребуется отдельная непрерывная
инструментация файловых операций с контролем потерь событий.
Это известный и явно обозначенный предел аудита, а не скрытая «полнота».

Приложение не получает доступ к Docker socket, не читает содержимое
PostgreSQL, не изменяет квоты, не удаляет файлы, не останавливает контейнеры
и не меняет работу MegaLoc. Отчёты доступны только владельцу в админке.

## Порядок дальнейшей работы

Сначала получить CSV и JSON с **реального VPS**, проверить `errors`,
`skipped_paths`, сопоставить суммы с `df`/Docker и собрать карту источников записи.
Затем, без удаления файлов, изучить временные операции, которые пропадают
до следующего сканирования. **Только после этого** обсуждать очистку или квоты.
