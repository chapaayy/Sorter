# MAP: ограниченная диагностика хранения (V2)

На новой установке постоянно работающий глобальный файловый наблюдатель не устанавливается. Учёт не основан на бесконечном обходе файлов Docker/containerd. Автоматический учёт и сверка относятся к следующему этапу.

## Ручной снимок

    sudo python3 PhotoSorter/tools/maintenance/audit_host.py --project-root /opt/Sorter

Корень storage определяется по защищённой конфигурации установки. Диагностика ограничена временем (60 секунд), количеством записей (100 000) и размером создаваемого отчёта (32 МиБ). Только последний снимок; при превышении бюджета предыдущий опубликованный отчёт сохраняется. Метаданные Docker читаются без удаления слоёв и без доступа к содержимому фотографий или секретам.

Отчёты: storage/system/audits/latest.json и latest.csv, только чтение в API, доступны владельцу через «Администрирование → Аудит сервера». Частичный снимок не является полным физическим учётом, ограничения отмечаются в отчёте.

## Ограниченное наблюдение

    sudo python3 PhotoSorter/tools/maintenance/audit_live.py --project-root /opt/Sorter

Сеанс завершается автоматически через 60 секунд или при достижении предела 90 МиБ. Следующий сеанс заменяет предыдущий, а не дописывает бесконечный JSONL. Состояние и события находятся в storage/logs/audit. Журнал диагностических операций ограничен отдельно в рамках общего бюджета аудита 100 МиБ. Одновременные сеансы блокируются. Inotify не восстанавливает события задним числом, не сообщает PID и не гарантирует наблюдение за всеми короткоживущими файлами.

Не запускать старую map-file-audit.service. Никаких глобальных prune, удаления containerd, изменения данных PostgreSQL или квот.
