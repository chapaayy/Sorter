# Outdoor PhotoSorter — VPS / MegaLoc Only

Приватная серверная сортировка фотографий рекламных конструкций. MegaLoc формирует группы **только по ФО** (порог `0.50`), затем сопоставляет их с постоянно хранимыми Образцами `SAM-xxxx`. Математика группировки и сопоставления перенесена без изменений из проверенной Stage 2.7.

## Развёртывание на VPS

Требования: Linux x86-64, Docker Engine с Compose v2, доменное имя и доступные TCP 80/443 (и UDP 443, если используется HTTP/3). Рекомендуется 8 vCPU, 24 ГБ RAM, от 200 ГБ NVMe. Виртуальные ядра могут работать медленнее локального процессора. Первый Docker build скачивает CPU PyTorch и зависимости, поэтому нужны интернет и место на диске.

```bash
git clone -b vps/docker-rebuild --single-branch https://github.com/chapaayy/Sorter.git
cd Sorter
cp .env.example .env
nano .env                 # укажи DOMAIN=sorter.example.com
chmod +x install.sh
./install.sh
```

Укажите **реальный домен** в `.env` (DNS A/AAAA на IP VPS). Всё остальное на первом запуске будет создано в `.env.generated`: пароль PostgreSQL и первоначальный пароль администратора. Скрипт выведет первоначальные данные: `admin` + сгенерированный пароль. **Не публикуйте, не удаляйте и не коммитьте** `.env.generated`! Сохраните пароль в менеджере паролей.

После установки откройте `https://<ваш-домен>`. Приватный сайт использует сессионную авторизацию. У Caddy отдельный контейнер, HTTPS-сертификаты живут в Docker volume. PostgreSQL, API и Worker не публикуют портов на VPS; снаружи доступны только 80/443.

**Веса MegaLoc не входят в репозиторий**: на Главной нажмите «Скачать MegaLoc» или скопируйте существующие файлы в `Models/models/megaloc/`, а исходники загрузчика разместите в `Models/cache/torch/hub/gmberton_MegaLoc_main/`. Ранее скачанные веса из `Models/megaloc/` тоже поддерживаются. Скачивание может быть долгим, использует диск VPS, но не запускается при каждом старте.

## Использование

1. «Главная» → «Образцы» → загрузить папку с `SAM-0001`, `SAM-0002`, ... (можно один раз, они остаются на VPS).
2. «Главная» → «ФО» → загрузить папку фотоотчёта; большие файлы передаются частями. При разрыве сети повторно выберите ту же папку — передача продолжится.
3. Убедиться, что есть веса MegaLoc. Выставить порог `0.50` и нажать «Начать обработку».
4. Смотреть прогресс/логи. На «Результаты» скачать общий ZIP или фотографии отдельного SAM; неопределённые отдельно в `_Неопределено`.

Один CPU Worker обрабатывает **одно задание одновременно**. API, загрузка и просмотр остаются доступны во время обработки. После перезапуска незавершённые задания получают статус `interrupted`, а уже завершённые остаются доступными. Изображения только копируются; оригиналы не перезаписываются.

## Что хранится где

| Каталог/том | Содержимое |
|---|---|
| `Models/models/` | постоянные веса MegaLoc, отдельно от кода |
| `Models/cache/` | torch/huggingface кэш загрузчиков, **не кэш ФО** |
| `PhotoSorter/data/references/` | библиотека Образцов по SAM |
| `PhotoSorter/data/uploads/` | партии загруженных ФО |
| `PhotoSorter/data/cache/megaloc/references/` | **только кэш эмбеддингов Образцов**; ключ: SHA256 изображения + версия модели |
| `PhotoSorter/data/runs/` | история запусков и манифесты |
| `PhotoSorter/data/outputs/` | Готовые фотки по SAM |
| `postgres_data` | пользователи, загрузки, задания, состояния, индекс кэша |
| `caddy_data`, `caddy_config` | сертификаты HTTPS и состояние Caddy |

Все данные в bind mounts и volumes переживают пересоздание контейнеров. **Кэш ФО отсутствует**; в одном запуске вычисленные признаки остаются только в RAM. Образцы кэшируются после этапа группировки ФО, так что алгоритм не получает информацию об Образцах преждевременно.

## Обновление

```bash
git pull
./install.sh
```

Не используйте `docker compose down -v` — эта команда удаляет тома PostgreSQL и Caddy! Не удаляйте `Models/`, `PhotoSorter/data/`, `.env.generated`. Никакой автоматической очистки исходников пока нет; следите за свободным местом на NVMe.

Для просмотра состояния:

```bash
docker compose --env-file .env --env-file .env.generated ps
docker compose --env-file .env --env-file .env.generated logs -f --tail=150 worker
docker compose --env-file .env --env-file .env.generated logs -f --tail=150 api
```

## Технические ограничения и статус проверки

- Передача файлов — собственный возобновляемый протокол `init` / `PATCH` с проверкой смещения и `finish`, **не** tus-совместимый сервис. Максимум одного файла — 60 МиБ; блок передачи — до 8 МиБ (интерфейс отправляет по 4 МиБ). Поддерживаются изображения, включая `jpg/png/webp/tiff/bmp`.
- Если пропали `.env.generated` или пароль администратора, потребуется восстановление учётных данных через серверное обслуживание PostgreSQL; потерянные секреты не регенерируются автоматически для уже созданной учётной записи.
- Проверены Python/JavaScript синтаксис и алгоритмы на unit-тестах. Полный `docker compose up` в среде разработки выполнить нельзя (Docker Engine отсутствует); до публичного использования проведите тест на VPS, проверку HTTPS, загрузок, сопоставления с реальными 189 ФО и резервного восстановления.
- Реальные зависимости PyTorch берутся из CPU-репозитория, версии закреплены в `docker/app/Dockerfile`.
