# Строгая библиотека конструкций и импорт образцов

## Формат одной конструкции

```text
КОД_ГОРОДА НОМЕР — АДРЕС
SAM 0004 — Гагарина 64
SAM 003 — Московское шоссе 15
SAM 01 — Полевая 12
TLT 3245 — Южное шоссе 10
```

- Между городом и номером **один пробел**. Между номером и адресом — **пробел, длинное тире U+2014, пробел**.
- Поддерживаемые коды: `SAM` (Самара), `TLT` (Тольятти). Новые коды добавляются централизованно в `backend/app/photos/construction.py`; сервер проверяет их при предпросмотре и при сохранении.
- Номер: 1–8 цифр, ведущие нули **сохраняются**: `SAM 01` и `SAM 0001` — разные идентификаторы.
- Адрес обязателен, не более 120 символов; без запрещённых Windows-символов в названии папки.
- Внутренний неизменяемый ключ: `SAM 0004`. Отображаемое имя: `SAM 0004 — Гагарина 64`. Адрес можно изменить отдельно, не перемещая фотографии и не меняя результаты MegaLoc.

## 1. Массовый импорт

```text
Образцы/
├── SAM 0004 — Гагарина 64/
│   ├── 001.jpg
│   └── 002.jpg
├── SAM 003 — Московское шоссе 15/
│   └── photo.png
└── TLT 3245 — Южное шоссе 10/
    └── 001.jpg
```

В разделе «Образцы» нажать «Загрузить образцы» → «Библиотека папкой», выбрать корневую папку. Можно выбрать и непосредственно одну правильно названную папку конструкции.

Проверка **до отправки**:
1. Клиент учитывает каждый файл в выбранном каталоге (включая неподдерживаемые расширения). Известные служебные файлы ОС (`Thumbs.db`, `ehthumbs.db`, `desktop.ini`, `.DS_Store`, без учёта регистра) **явно записываются в список пропущенных**, не считаются фотографиями и не блокируют импорт. Другие неподдерживаемые файлы остаются ошибками.
2. Сверяет точный формат названия папки, допустимые форматы, пустые и слишком большие файлы, глубину расположения.
3. Сервер подтверждает код города и сравнивает адрес каждой конструкции с уже сохранённым.
4. Показаны новые конструкции, существующие конструкции для дополнения, число файлов и подробный перечень **всех** ошибок.
5. Пока хотя бы одна ошибка не исправлена, кнопка загрузки заблокирована. Нельзя молча пропустить часть библиотеки: учитываются отдельно подходящие фотографии, ошибки и известные служебные файлы ОС. Служебные файлы не отправляются на сервер и не удаляются с компьютера.

**Повторное добавление конструкции не ошибка. Для уже существующих конструкций браузер сравнивает SHA-256 выбранных файлов с серверным списком готовых образцов и пропускает точные совпадения **до сетевой передачи**, когда доступен WebCrypto. Если локальная проверка недоступна, сервер всё равно проверяет SHA-256 и не дублирует запись.** При совпадении ключа и адреса новые фотографии добавляются к прежним. Файлы с одинаковым SHA-256 внутри одной конструкции не получают вторых записей в базе. Если адрес отличается, импорт блокируется и показывает сохранённый адрес: исправьте папку или отдельно измените адрес конструкции. Автоматического изменения адресов и удаления старых фотографий нет.

**Ограничение браузера:** выбор каталога через `webkitdirectory` перечисляет файлы, но не сообщает о полностью пустых директориях. Пустые папки без файлов нельзя подтвердить на клиенте; конструкции без фотографий не создаются.

## 2. Добавление отдельных изображений

Открыть существующую конструкцию → «+ Добавить фото» → выбрать изображения. Названия фотографий свободные; папки выбирать не требуется. Ключ конструкции известен из выбранной карточки.

## Допустимые файлы, докачка, защита данных

- JPG/JPEG, PNG, WebP, TIFF/TIF, BMP; 60 МиБ на фото.
- Параллельные передачи задаются в «Настройках» (1–10, по умолчанию 5); файл передаётся блоками до 16 МиБ с докачкой.
- На сервере: проверка размера, фактического изображения через Pillow, SHA-256; повторения по содержимому не создают новых образцов.
- Во время queued/running/stopping MegaLoc изменения образцов запрещены.
- Старые записи `SAM-xxxx` и исторические manifests **не переименовываются**. Старые имена не подходят для **нового массового импорта**; ранее сохранённые фото остаются доступны. При необходимости перевода старой библиотеки на новый стандарт потребуется отдельная согласованная миграция, а не скрытая замена идентификаторов.
- Новая миграция `0008_reference_constructions.sql` **аддитивная**: сохраняет существующие uploads, ZIP и историю; адреса хранятся отдельно от стабильных ключей.

## Модули

- `frontend/src/utils/referenceSelection.ts` — строгий разбор выбранных папок и полный отчёт об ошибках.
- `frontend/src/features/references/ReferenceDirectoryImporter.vue` — предпросмотр массового импорта.
- `frontend/src/features/references/ReferencePhotoUploader.vue` — отдельные фото в выбранную конструкцию.
- `frontend/src/composables/useReferenceTransfer.ts` — общая передача и докачка.
- `backend/app/photos/construction.py` — авторитетные коды городов и парсер нового имени.
- `backend/server/services/construction_catalog.py` — предпросмотр, адрес, регистрация конструкций.
- `backend/server/uploads.py` — финализация, дедупликация и защита оригиналов.


## Фактическая загрузка

Загрузка доступна при любой заполненности FIFO. Каждая выбранная партия
образцов сначала проходит валидацию, затем регистрируется полный server-side
manifest и UUID файлов, после чего загружается в `data/reference_staging/`.
Обрывы и перезагрузка браузера восстанавливаются повторным выбором той же папки.
Когда все файлы подтверждены, автоматически создаётся ровно одна задача
`reference_preparation`. Публикация библиотеки происходит только после
полной подготовки MegaLoc. ФО никогда не сканирует живой каталог `references`.
См. `REFERENCE_PIPELINE.md`.
