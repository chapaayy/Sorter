Ветка `feature/storage-architecture-v2`, исходный SHA c6d77ebb. Единый контракт [storage-layout-v2.json](storage-layout-v2.json) активен в коде. **Финальная приёмка не равна реализации:** статус и доказательства — [отчёт](STORAGE_V2_FINAL_REPORT.md), история этапов — [прогресс](STORAGE_V2_PROGRESS.md). ## Границы

- Host root по умолчанию `/opt/Sorter/storage`, закрепляется в root-only .env.generated. `MAP_STORAGE_ROOT` — host pin, `MAP_APP_STORAGE_ROOT` — process root (в контейнере /storage/app, в тестах изолированный override). Один app bind для всех четырёх Python-сервисов с UID/GID 10001:10001; общая ФС необходима для atomic rename/hardlink. Rootfs read-only, /tmp 64 MiB, /var/tmp 32 MiB; нативный TMPDIR — managed leased scratch.
- PostgreSQL 17 Alpine (70:70), Caddy (root) имеют отдельные постоянные binds `infrastructure/postgres/data`, `infrastructure/caddy/{data,config}`. App не получает их, updater private paths или Docker socket. PostgreSQL на private network без публичного порта. Updater control read-only; только API видит узкий Unix RPC.
- Typed keys: user BIGINT, batch/upload/session UUID, run ID YYYYMMDDTHHMMSS-12hex, full SHA-256, полный model signature. Display name, SAM address and browser filename are metadata, not filesystem authority. Descriptor-relative no-follow access. SQL owner relation + path validation, immutable media, atomic publish and recovery. Unknown files are reported, never blindly removed.
- Tree: [PROJECT_MAP](../PROJECT_MAP.md), [all 51 categories](STORAGE_V2_FINAL_CATALOG.md). No active mounts to PhotoSorter/data/Models; no legacy named volumes. Three reserved/virtual namespaces (run_state, reference_gallery, FO spilled embeddings) are not independent active writers. Host config, engine shared layers, tmpfs, external backups/diagnostics, browser storage are distinct boundaries.

## Reference and FO policy

- Personal: original, normalized, result media/metadata, owner-scoped WebP. A same-owner hardlink is counted once; a real copy charges independently. Originals are immutable; normalized media is not temporary.
- Shared references: CAS object keyed by content SHA-256, same object may belong to different constructions and versions. Published gallery is SQL, not another file copy. FIFO claim pins immutable version and model signature. Current pointer, historical members, retained jobs and pending/retryable imports protect objects.
- Unpinned superseded versions may retire member sets after 30 days; headers remain. After last dependency disappears, object/embedding candidate waits 24h, then recheck graph and exclusive reader lock. No age-only purge of active embeddings or objects. Thumbnails also require dependency disappearance and 24h grace, personal scope per account. Abandoned transfers expire after 30 days inactivity only after locks and recheck.
- Reference embeddings use model/source/preprocessing signature plus digest, NPY checksum/dimension/dtype/finite validation. Unchanged model restart/redeploy does not invalidate. FO vectors remain RAM; temporary video frames and export staging are cleaned on terminal/failure or proven abandonment. Details: [lifecycle](DATA_LIFECYCLE.md).

## Temporary pool and model

- All ZIPs on demand: `app/temporary/archives/results/{run_id}/` and `archives/references/{cache_key}.zip`. CRC validation before publication; same-key serialization, shared folder pin for live readers/builders, exclusive nonblocking cleanup. 3600 s from publication, sweep ~30 s; no archive retry queue, no ZIP completion gate. Temporary occupancy and future reservations separate from personal charge.
- Typed upload, transcode, frame, processing, atomic and native scratch paths. Leased scratch is removed in finally; crashed unlocked directories eligible after 3600 s. Accepted transfers remain resumable; explicit deletion and dependency checks, not indiscriminate rm.
- Permanent verified MegaLoc bundle: `app/models/megaloc/{weights,source,metadata}`. Official weights gberton/MegaLoc revision a0f34722c4297ff787e022433799250180860af7, SHA-256 d4f9f2bcb60018f91eb6a8e061ed054fd55654e10c2569cf13841ea986ffb4f8; source gmberton/MegaLoc revision 5fe0dd697c4a70ba3e23607f6716ab3c606b16db. Explicit download from admin into typed leased temporary namespace, verification of hashes plus real finite 8448-dimensional inference before marker publication. Runtime offline, no fallback to hub downloads. Preserve valid bundle and cached embeddings across deployment. Repair damaged bundle explicitly.
- Only technical providers `app/cache/{torch,huggingface,xdg}` are disposable via explicit offline root maintenance after verified independent model, idle app and exclusive runtime lock. No automatic provider or embedding eviction.

## One registry, reservations and health

- PostgreSQL storage registry has per-path physical evidence (device/inode, nlink, logical st_size, st_blocks*512). Unique observed device/inode attribution avoids duplicate blocks, prioritizes persistent owner over temporary link and original over derivative. Personal charge is max(logical, allocated) once per valid owner/inode. Cross-owner inode conflicts, wrong path owner, missing/extra or invalid result manifests and unknown objects are diagnostics. Result membership is sampled generation, not duplicate full manifest.
- Producer hooks coalesce dirty keys; background reconciler bounded 1024 keys / 250 ms slice, periodic full descriptor walk (~900 s), temporary sampling ~5 s, aggregate refresh ~15 s, stale after 60 s. Result manifest validation bounded 256 rows/250 ms. No filesystem walk inside HTTP handlers. Summary is an observed snapshot, not complete kernel lifetime/event trace.
- Disk, temporary, personal budgets use the same ledger plus unfinished receipts and transient leases. PostgreSQL advisory transaction lock serializes admission. Durable offset bounds disk credit; publication hands off exact evidence before releasing lease. Losing DB session alone cannot release active kernel writer. Unknown files not auto-deleted. Limits nullable, disabled default except physical floor. Effective floor max(existing guard, configured); updater retains independent 8 GiB minimum. Lowering limits never deletes data; enabled decisions require fresh reconciled evidence. No app-level guarantee against unrelated OS writes.
- Owner UI: overview, accounts, temporary, limits, diagnostics, maintenance. Pagination, bounded snapshot/CSV (25,000 paths), live detail vs timestamped aggregate, unknown/stale visible. Fixed maintenance only; preview is eligibility estimate. Host samples protected dirs, log budgets, WAL, Docker metadata, outside-MAP difference, unlinked-open descriptors (lower bound) and tmpfs separately. Directory metadata/shared OS/engine layers and concurrent writes prevent exact equality with df. No global purge or automatic VACUUM FULL.
- Health: native Docker healthchecks on PostgreSQL/API; Caddy must proxy real HTTPS; worker/thumbnail/cleanup write independent DB heartbeats every 10 s, alive threshold 35 s. A running container alone is not healthy. VM acceptance requires all units active/enabled, exact service identities, new heartbeat instances after reboot and update and observed advancement, real PostgreSQL query and authenticated system status.

## Infrastructure, logs and recovery

- One revision-labeled app image, preserve current and previous, isolated marked BuildKit builder. No global prune. Docker json-file fallback 2 MiB x2. Managed budgets MiB: api 50, worker 100, cleanup 30, thumbnail 30, Caddy access 100/runtime 30, PostgreSQL 100, processing 512 aggregate/20 per run, models 30, updater 50, audit 100. App JSONL one active + four rotated; Caddy native 20/6 MiB segments plus four retained, omit URI/headers; PG native rotation 10 MB or 60 min, only closed segments pruned. Active segments/asynchronous cleanup can briefly overshoot budgets.
- Root `map-updater.service` fixed RPC status/check/update and storage-cache/storage-logs. Trusted origin, pinned feature branch, clean tracked state, fast-forward, space checks, activity lock, protected logical DB/config backup, isolated build/workspace, switch and actual health. Failure after switch preserves marker and backup; no automatic destructive restore. `map-log-maintenance.timer` cleans closed PG logs. No public root shell through app.
- Snapshot schema 3: persistent app, resumable parts, model, references, Caddy native state, protected env and installation metadata, logical PG dump, safe hardlinks/symlinks and digests. Excludes reproducible temporary, logs, live PGDATA and updater work. Independent storage and isolated restore-test; no automatic production failover. [Backup](BACKUP_RESTORE.md), [deployment](DEPLOYMENT.md), [rollback](ROLLBACK.md).
