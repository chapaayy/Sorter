# Этап 4 — приёмка PhotoSorter перед внедрением

**Статус:** раздел «Обработка» и автоматические проверки разработаны в GitHub. Реальный VPS, сеть и точность MegaLoc нельзя считать проверенными только по GitHub Actions.

## Автоматизированные проверки

- Backend: регрессии загрузок, манифестов, докачки, очереди, автообработки, образцов, ZIP, миграций и безопасности; новые фильтры `GET /runs?scope=active|history` и совместимость без `scope`.
- Frontend: Vitest расчёта статусов без вымышленных процентов/длительностей; Playwright Chromium/WebKit desktop/mobile для новой вкладки, Worker, очереди, остановки и истории.
- Restore: `pg_dump` → `pg_restore` в изолированную PostgreSQL.
- Docker runtime: сборка/старт изолированных контейнеров, health и background workers.

CI не имитирует физический VPN и не использует реальный пользовательский VPS.

## Ручной чек-лист перед внедрением на действующий VPS

**До проверки:** сохранить проверенный backup PostgreSQL + `PhotoSorter/data` + `Models` + `.env.generated`, проверить восстановление на отдельном тестовом сервере. Обновление рабочего VPS требует отдельного разрешения.

1. Короткий обрыв VPN (1–2 сек): после восстановления передача продолжается с подтверждённого смещения, не создаёт второй оригинал или job.
2. Долгое отключение сети: ожидание/повтор соединения, затем докачка; отсутствие потери уже финализированных ФО.
3. Перезагрузка браузера во время передачи: пользователь выбирает ту же папку, IDs и размеры совпадают с зарегистрированным серверным манифестом.
4. Потерянный ответ на последний `finish`: `GET /batches/{id}/upload-manifest` показывает `complete`, повторное подтверждение идемпотентно.
5. Несколько новых партий с автообработкой: FIFO очередь, один running Worker, нет параллельного инференса.
6. Перезапуск API/Worker на тестовом стенде: старые queued сохраняются, запущенная задача корректно получает `interrupted`, новое задание не дублируется.
7. Повтор регистрации манифеста и конкурентная постановка: один оригинал на UUID и одна автоматическая задача на партию.
8. Повторная ручная обработка из «ФО» с другим порогом: оба запуска доступны в истории, предыдущий успешный результат не исчезает после сбоя нового.
9. Старые партии без манифеста: открываются как раньше, не начинают автообработку без явного согласия, прежние ZIP и результаты сохраняются.
10. Desktop/mobile: панель MegaLoc, состояние Worker heartbeat (alive/no signal), реальный прогресс, очередь, подтверждение остановки, история и отсутствие второй формы запуска; Safari на реальном iPhone проверяется отдельно от CI WebKit.

## Решение о внедрении

Зафиксировать результаты каждого сценария. При потере ФО, повторном автоматическом запуске или параллельном MegaLoc выпуск запрещён. Для обновления нельзя использовать `docker compose down -v`, удалять `Models`, БД, `.env.generated` или рабочие данные.

См. [BACKUP_RESTORE](BACKUP_RESTORE.md), [ROLLOUT](ROLLOUT.md), [ACCEPTANCE](ACCEPTANCE.md) и [TESTING](TESTING.md).
