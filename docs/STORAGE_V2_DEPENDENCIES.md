## Additional source verification
- Upstream MegaLoc source at inspected SHA [5fe0dd697c4a70ba3e23607f6716ab3c606b16db](https://github.com/gmberton/MegaLoc/tree/5fe0dd697c4a70ba3e23607f6716ab3c606b16db): `megaloc_model.py` (blob 3559bc209f7194d90c6ee3e2350981328af8c743) constructs the DINOv2 backbone, aggregator and Torch modules directly; forward performs tensor operations and resize, no explicit checkpoint fetch/write. `hubconf.py` (blob 7c945bf8c94a24867ffc778ed06665d8d48354c8) separately calls HF download for config.json and model.safetensors in get_trained_model. MAP loader imports the model directly and does not call that hub entry point. This is evidence about inspected source, not a guarantee that arbitrary downloaded main revisions or native libraries behave identically. Pinning and actual offline verification remain stage 5. MAP requirements pin huggingface-hub 0.36.0, safetensors 0.4.5, timm 1.0.15, Pillow 11.0.0, NumPy 1.26.4 and pillow-heif 0.20.0; don't treat package dependencies as evidence of a file writer without a reachable call.
- Frontend `utils/upload.ts` stores resume client IDs under ps.up.v3.* in localStorage, slices selected File into bounded chunks, validates server offsets and checks prefix SHA256 when the user reselects the file. `utils/foTransfer.ts` matches registered manifest relative names/sizes and upload IDs. `utils/referenceTransfer.ts` stores sessionId/IDs/manifestKey in localStorage and uploads slices; `utils/referenceDuplicates.ts` hashes selected files in browser RAM. These are client_storage and HTTP transfer inputs, not server filesystem paths. Preserve resume/offset validation and do not use relative names as path authority. `stores/uploadSettings.ts` and `stores/theme.ts` persist preferences only. `PendingUploads.vue` uses pending/manifest and finish/cancel API, not direct files; `ReferenceLibrary.vue` consumes gallery cursor, original/preview/play/thumbnail URLs, side and deletion API, and native download anchor. `ThumbnailGrid.vue` and `ImageViewer.vue` consume URLs. `RunDetail.vue` polls run/batch state and stop; no retry archive call there. Archive retry/status methods in API client remain candidates for later dead-code removal, not storage producers.
