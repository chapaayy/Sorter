# Откат PhotoSorter (beta) — только с проверенной копией

Откат — восстановление конкретного предыдущего рабочего Git SHA/образа, а **не** переключение сайта на `/v3/`: старый frontend удалён. Качественный rollback PostgreSQL и файлов не заменяется `git checkout`.

## Перед сменой версии

1. Остановить новые uploads, jobs и подтверждения ZIP; проверить активные задачи/скачивания. Никогда не запускать старый и новый MegaLoc Workers одновременно.
2. Сохранить `git rev-parse HEAD`, `docker compose ps`, Compose mount IDs, `.env`, `.env.generated`, состояние Caddy и размеры `PhotoSorter/data` / `Models`.
3. Сделать **согласованный** снимок файлов и `pg_dump --format=custom` после остановки writers; перенести в отдельное защищённое хранилище и проверить restore на **пустой изолированной базе**.
4. Проверить, что для предыдущего commit сохранились Docker build исходники, network/DNS и допустимый cpuset.

## Откат только приложения

Если схема PostgreSQL и новые записи обратно совместимы, допустим возврат прежнего кода/образа с сохранением volumes, но **только после проверки совместимости схемы**. Версионируемые миграции 0001…0007 — аддитивные, однако совместимость старого кода с новыми состояниями БД не гарантируется автоматически.

```bash
# Пример только после решения об откате: <PREVIOUS_VERIFIED_SHA> — фактически работавший SHA.
git switch --detach <PREVIOUS_VERIFIED_SHA>
bash ./install.sh --check
# После проверки соответствия БД и бэкапа оператор отдельно решает о --deploy.
```

Следить за активными jobs, безопасным изменением статусов и auth/session; перед возобновлением обработки удостовериться в здоровых `api`, `worker`, `thumbnail`, `cleanup`, `postgres`.

## Если нарушены данные или схема

Нужен **полный** согласованный restore прежней базы + файлов, а не выборочное удаление таблиц. Восстановление выполняется на отдельном стенде, затем переносится по согласованной процедуре. Не исполнять `DROP TABLE`, `DROP COLUMN`, `rm -rf`, `docker compose down -v` для «починки» без явного решения владельца. Отдельно учесть резервирование сертификатов Caddy Docker volume, которые не входят в `snapshot.py`.

## После восстановления

Пройти login, `/api/health`, статус services, БД, старые ФО/SAM, gallery, full ZIP, checksum, контроль настоящего MegaLoc baseline. Зафиксировать commit, snapshot SHA, время и результаты проверки.

Связанные документы: [BACKUP_RESTORE](BACKUP_RESTORE.md), [DEPLOYMENT](DEPLOYMENT.md), [SINGLE_SITE_INSTALL](SINGLE_SITE_INSTALL.md).

## Особое условие после активации FIFO

После включения staged reference jobs **нельзя просто выключить** `PHOTOSORTER_UNIFIED_QUEUE` и запустить старый Worker: он не умеет исполнять `reference_preparation` и способен обойти зависимость. Сначала прекратить новые загрузки/claim, зафиксировать все queued/running/prep/ack статусы и пути, выполнить проверенный staging restore/согласованное операторское решение. Для обычного отката UI до активации flags достаточно прежнего pinned image; новые аддитивные таблицы сохраняются. Реальное переключение/restore только после разрешения владельца.
