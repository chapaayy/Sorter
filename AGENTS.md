# AGENTS.md — обязательные правила изменений OUTDOOR PhotoSorter

1. **MegaLoc math frozen.** Не менять `app/recognition/`, порядок ФО→группы→SAM, порог по умолчанию 0.50, score/manifest без отдельного разрешения и baseline regression.
2. Изменения делать по одному утверждённому этапу в **новой ветке от `vps/docker-rebuild`**. Не менять `main`, исходную ветку или VPS без разрешения; фиксировать base SHA.
3. Никогда не удалять и не копировать секреты, `Models/`, `PhotoSorter/data/`, библиотеку SAM, PostgreSQL volumes или реальные фото. Миграции только аддитивные/обратимо совместимые. Сначала бэкап и restore-test на тестовом окружении.
4. Любое удаление партии — **строго по доверенному UUID из БД**, с защитой path/symlink traversal и журналом состояния. Не удалять shared reference/model cache вместе с партией. Запускать cleanup только при подтверждённом ZIP либо явном DELETE.
5. Не считать HTTP ZIP ответ доказательством сохранённого файла: требуется явное подтверждение пользователем. Retention: UTC +2 **календарных** месяца; предупреждение за 7 дней; очередная обработка сбрасывает подтверждение.
6. Hard Link допускается только при совпадении файловой системы/правах и неизменности исходника. Если нет — безопасная копия/ошибка. Нельзя перезаписывать оригинал или существующий результат, массово менять старые outputs. Hardlink — не бэкап.
7. Не ломать текущую auth/session/HTTPS, resumable PUT/PATCH/checksum, ZIP stream или кэш **только Образцов**. Любая новая API ручка должна использовать текущую middleware auth и Origin.
8. Один модуль — одна ответственность. HTTP API / service / DB / storage / Worker разделять; переносить логику без двух параллельных реализаций. Не создавать пустые файлы ради структуры.
9. Никогда не менять `install.sh` так, чтобы он регенерировал действующие секреты. Не добавлять пароли/домены/ключи/фотографии в Git.
10. После каждого изменения обновлять `README.md`, `AGENTS.md`, `PROJECT_MAP.md`, `FILE_INDEX.md` и релевантные `docs/`; запускать compile/tests/CI, сообщать непроверенные пункты и ошибки.
11. Изменения базы, реального хранения и фоновой очистки — особенно опасны. **Не деплоить stage1 код на рабочий VPS** до backup/restore испытаний и отдельного подтверждения владельца.
12. Не переходить к этапу 2 по собственной инициативе. Этап 1 завершать только после фактической проверки контрактов, а не визуальных заглушек.

## Дополнительные правила этапа 2

13. Preview задачи строго после SHA/Pillow finalize, асинхронно. Never alter originals; thumbnail cache != MegaLoc reference embedding cache.
14. Не менять MegaLoc math для производительности. Только один running worker под global advisory lock + DB gate; queue position и stop должны отражать фактическое состояние БД.
15. ZIP и оригинальный viewer обязаны освобождать operation lease после disconnect, иначе удаление блокируется.
16. Журналы JSONL и Docker stdout ограничивать; не возвращать все события гигабайтным ответом.
17. Диск: при нехватке резерва отвечать 507 для новых uploads, никогда не удалять неподтверждённые полноценные ФО ради места.
18. CPU cpuset 0–6/7 threads — **гипотеза для 8-vCPU staging**, не применять на живом VPS без подтверждённых измерений и отдельного согласия.
19. Системные и новые gallery API сохраняют auth/cookies/origin. Клиент никогда не передаёт абсолютные filesystem пути.

## Stage 3 frontend и безопасность

20. Vue 3 + TypeScript — единственный клиент, живёт в `PhotoSorter/frontend/src` и отдаётся на `/`. Не возвращать отдельный `frontend/static`, версионные префиксы `/vN/` или вторую сборку. API остаётся на `/api/`.
21. Фронтенд не хранит в localStorage пароли, cookie, SHA/содержимое ФО или результаты. Browser передаёт идентификаторы файлов/партий/запусков, только backend владеет физическими путями.
22. Full ZIP download **не означает** получение пользователем: ретеншн запускается только отдельным подтверждением после проверки сохранения полного архива. Деструктивные операции требуют явного осмысленного подтверждения.
23. Для галерей/логов пользоваться cursor pagination, lazy thumbnails, не загружать гигабайтные manifests целиком в UI. Оригинал только в ImageViewer.
24. Компоненты должны оставаться модульными; один файл — одна задача/экран. Для каждого нового Vue модуля обновлять FILE_INDEX и PROJECT_MAP.
25. Интерфейс адаптивен, touch target ≥44px, keyboard/Escape, light/dark tokens едины, не использовать хардкод абсолютных CDN/FS URL и фиктивные модели/оценки/прогресс.
26. Перед PR гонять `npm ci && npm run build && npm run test`, backend CI и Playwright chromium/webkit; production VPS/реальные SAM/веса по-прежнему off limits.

## Stage 4 — обязательные ворота production

27. Не объявлять «production ready» только по GitHub CI: нужны **реальный 189/1315 baseline** из того же набора, сопоставимый MegaLoc checkpoint/signature, real restore и отдельное согласие пользователя. Синтетические fixtures не считать реальными фото.
28. Backup CLI не останавливает пишетущие сервисы: оператор обязан добиться quiesced state до `--ack-writers-stopped`. Внешний storage должен быть независимым, зашифрованным; `.env.generated` ни в какие CI artifacts не загружать.
29. Система кода не должна выполнять deployment, SSH к VPS или удаление реальных файлов без отдельно выраженного владельцем разрешения; `install.sh --check` безопасен и read-only, для апгрейда `PHOTOSORTER_APPROVE_UPGRADE=VERIFIED_BACKUP_AND_ROLLBACK` только после проверки, не автоматизировать установку этого токена.
30. В исторически опубликованных runs не уничтожать и не перемещать SAM reference-paths; текущий SAM rename/delete при ссылке в manifest возвращает 409 (fail closed).
31. Изображения, ZIP path и распаковка резервной копии ограничены; не доверять клиентским путям, symlink, `../`, `\x00`. Для restore нужен пустой `sorter_restore_*` DB и staging marker.
32. `0007_service_heartbeat.sql` — **только additive schema**; старые данные/sessions/jobs не менять. Здоровье worker=heartbeat, а не `0 queued`.
33. По запросу владельца старый `frontend/static` удалён из release-ветки. Это не разрешение удалять живые фото, секреты, модели или Docker volumes. Сохранять бэкап и rollback commit; `Models/models` и `Models/cache` независимы.
34. Изменения `app/recognition/` запретить и в Stage4, без отдельного benchmark+approval.
